# 마음부부 — 관계 통역 엔진 스펙 마스터 문서

> **Engine Specification — Master Document v3**
> 이중 트랙 병행 설계: 심리상담 트랙 (애착 · EFT) × 기독교 트랙 (Powlison / Keller / Tripp)
> IP 원본 · 프롬프트 코드화 · 투자/파트너십 · 개발 위탁의 단일 진본
>
> *두 트랙은 대립이 아니라 공존한다 — 신앙인도 세상 속에서 심리적 지혜를 활용하며 빛과 소금이 된다*

---

## 0. 이 문서의 위치 — 왜 '마스터 문서'인가

이 문서는 마음부부 관계 통역 엔진의 **단일 진본(Single Source of Truth)**이다. 흩어진 아이디어가 아니라, 다음 모든 하위 산출물이 이 문서 하나에서 파생되도록 설계되었다.

- **프롬프트 코드화** — 4장의 프롬프트 아키텍처가 그대로 LLM 프롬프트 라이브러리로 전환된다. → `translation-prompts.ts`로 구현 완료
- **개발 위탁 / 내재화** — 6장의 데이터 구조와 8장의 화면·기능 명세가 개발 스펙이 된다. → `translate-route.ts`에 D1 스키마 포함
- **투자 · 파트너십** — 1장의 자산 정의와 9장의 방어막이 IP 실사의 근거가 된다.
- **교회 · 교단 채택** — 3장의 기독교 트랙과 감수 체계가 신뢰 근거가 된다.

> **핵심 설계 원칙 — 이중 트랙 병행**
> 심리상담 트랙(애착·EFT)과 기독교 트랙(Powlison/Keller/Tripp)은 사후에 덧붙인 옵션이 아니라, 엔진의 뼈대에서부터 병행으로 설계된 두 개의 대등한 해석 경로다.
> 두 트랙은 '공통 탐지 레이어'를 공유하되, '해석·개입 레이어'에서 분기한다. 사용자는 자신에게 맞는 트랙을 선택하고, 트랙 내에서 강도를 조절한다.

## 1. 무엇이 자산인가 — 자산 등급 정의

엔진 자체는 팔리지 않는다. 엔진이 만들어내는 '검증되고 방어된 결과물'이 자산이다. 자산화는 두 축 — 엔진을 지키는 것(방어)과 엔진으로 매출을 만드는 것(수익) — 으로 진행된다.

| 등급 | 자산 | 성격 |
|---|---|---|
| A급 | 기독교 상담 전문가 본인의 감수 역량 | 경쟁사가 돈으로 살 수 없음. 교회 시장의 신뢰 진입 조건 |
| A급 | 이중 트랙 + 신학/톤 슬라이더 설계 | 심리상담·기독교 두 시장을 하나의 엔진으로 커버하는 구조 IP |
| A급 | 증거 등급 기반 안전 가드레일 | 예측·정죄·학대방치 배제. 소송·평판 리스크 방어 자산 |
| B급 | 마음커플·마음풀 인프라 | JWT SSO·D1·Toss결제·상담연계·Anthropic API 재사용 |
| B급 | 마음수달·마음곁 멀티모달 분석 | 녹음·영상 분석 기능 재사용 → 비언어 탐지의 기반 |
| B급 | 마음커플 초대코드(동의) 로직 | 쌍방 동의 게이트로 재사용 → 감시 방지 + 법적 안전 |
| B급 | CTS·기독교TV 파트너십 경험 | 교회 유통 채널의 기존 지렛대 |
| C급 | 통역 프롬프트 라이브러리 | ✅ 구축 완료 — `translation-prompts.ts` |
| C급 | 관계 기억 데이터 구조 | 6장에서 정의 — D1 스키마 구현 완료 |
| C급 | 검증된 케이스 뱅크 | 구축 대상 — 상담사 자산이 데이터 자산으로 전환되는 지점 |

> **자산 집중 원칙**
> ① 범용 AI가 못 하는 것에만 자산을 집중한다. 단순 통역은 ChatGPT도 한다. 해자는 '관계 기억 + 상담사 감수 + 신학 정확성'이다.
> ② 감수 역량을 시스템화한다. 본인 검수가 병목이 되면 확장 불가. 케이스 뱅크·체크리스트로 감수 노하우를 문서 자산으로 복제한다.
> ③ 데이터를 처음부터 자산으로 설계한다. 통역 요청·교정·성공 케이스는 이 시장의 독점 데이터가 된다(개인정보 보호 전제).

## 2. 엔진 아키텍처 — 3층 구조 + 트랙 분기

엔진은 3개 레이어로 작동한다. 1층(탐지)은 두 트랙이 공유하고, 2층(해석)과 3층(개입)에서 트랙별로 분기한다. 이 구조가 '하나의 엔진, 두 세계관'을 가능하게 하는 핵심이다.

**입력은 다중 양식(멀티모달)이다.** 텍스트(카톡 붙여넣기)에 더해, 쌍방 동의 하의 음성 녹음·영상이 1층 탐지 레이어로 들어온다. 마음수달·마음곁에 이미 구현된 녹음·영상 분석 기능을 재사용한다. 멀티모달 입력은 텍스트가 놓치는 비언어 신호(어조·표정·시선)를 포착해 탐지 정확도를 근본적으로 끌어올린다. 단, 모든 녹음·영상 입력은 5장의 '동의 게이트'를 통과해야만 활성화된다.

### 2.1 전체 흐름

| 레이어 | 역할 | 내용 |
|---|---|---|
| ① 공통 탐지 레이어 | 무엇이 일어나고 있나 (관찰 기반, 두 트랙 공통) | 행동 신호 탐지: 비난 / 경멸 / 방어 / 담쌓기, '거친 시작' 패턴. 입력: 텍스트 + (동의 시) 음성·영상 비언어 신호 |
| ② 트랙 선택 | 사용자 세계관에 따른 경로 분기 | 심리상담 트랙 ↔ 기독교 트랙 |
| ③ 해석 레이어 | 왜 그런가 (트랙별 렌즈) | 심리상담: 애착·EFT 악순환 고리 / 기독교: 6렌즈(마음·우상·성화·언약·용서·복음) |
| ④ 강도 조절 | 트랙 내 미세 조정 | 심리상담: 감정 깊이 / 기독교: 신학 강도 + 목양 톤(2세대 기본) |
| ⑤ 개입 레이어 | 그래서 어떻게 | 4모드(수신·발신·중재·관점) 재작성 + 개선 활동 제안 + 공통 안전 오버라이드 |
| ⑥ 회복 레이어 | 관계가 실제로 움직이게 | 개선 활동 → 실행 피드백 → 재해석 → 기억 축적 → 커뮤니티 공감 (7장) |

### 2.2 통역 4모드 (트랙 공통 인터페이스)

**A. 수신 통역 — "저 말이 무슨 뜻이야?"**
배우자가 한 말을 입력 → 표면 문장 뒤의 감정·니즈·숨은 요청을 풀어줌. 심리상담 트랙은 애착 신호로, 기독교 트랙은 마음의 갈망으로 통역.

**B. 발신 통역 — "이걸 어떻게 말하지?"**
하고 싶은 말을 입력 → 상대가 방어하지 않을 표현으로 재작성. '거친 시작'을 '부드러운 시작'으로 교정하는 것이 핵심 개입점.

**C. 중재 통역 — 싸운 대화 전체 분석**
카톡 대화 전체 입력 → 각자의 진짜 입장 + 오해가 생긴 지점 + 다음 한마디 제안. 항상 양쪽의 취약함을 동시에 드러내 '편들기'를 방지.

**D. 관점 통역 — "상대는 이걸 어떻게 느꼈을까?"**
같은 사건을 배우자 입장 버전으로 통역해 보여줌. 범용 AI와 갈라지는 결정적 차별점 — 대부분의 도구는 '내 입장에서 상대 말 해석'만 하지만, 관점 통역은 '상대 입장에서 나를 어떻게 볼지'를 구조적으로 보여준다. 양방향 비대칭을 해소해 공감을 만든다.

> **관점 통역의 이론적 근거 (트랙별)**
> - 심리상담 트랙: EFT의 '재연결(reconnection)' — 상대의 1차 정서(두려움·외로움)를 인식시켜 악순환 고리에서 빠져나오게 하는 핵심 개입.
> - 기독교 트랙: Keller의 '미래 영광의 시선' — 배우자의 현재 결점 뒤에서 하나님이 빚으시는 사람을 보게 하는 언약적 관점.

## 3. 이론 뼈대 — 증거 등급과 이중 트랙

이 장은 자산의 방어막이다. '얼마나 유명한가'가 아니라 '얼마나 검증됐나'로 이론을 등급화하고, 등급에 따라 엔진에서 쓰는 방식을 다르게 규정한다. 검증된 만큼만 말하고, 나머지는 **단정이 아닌 가설**로 제시한다.

> **두 트랙의 관계 — 대립이 아니라 공존**
> 심리상담 트랙과 기독교 트랙은 '세속 대 성경'의 대립 구도가 아니다. 신앙인도 세상 속에 살며, 성경은 그들에게 세상의 빛과 소금이 되라 권한다.
> 심리상담 트랙은 하나님이 창조하신 세계에서 관찰·검증된 인간 이해(애착·EFT)를 활용하는 경로이고, 기독교 트랙은 그 위에 복음적 해석을 더하는 경로다. 사용자는 자신에게 맞는 언어를 선택하며, 두 트랙은 하나의 엔진 안에서 공존한다.

### 3.1 심리상담 트랙 이론의 증거 등급

| 이론 | 증거 강도 | 엔진 사용 방식 |
|---|---|---|
| EFT (정서중심치료) | ★★★★★ | 핵심 해석축. RCT 메타분석(33편·2,730명) 검증. '악순환 고리'가 2층의 심장 |
| 애착이론(성인) | ★★★★☆ | 해석의 토대. 단 '유형 낙인' 아닌 '차원'으로 적용 |
| Gottman 4독소 | ★★★☆☆ | 1층 신호 탐지용으로만. '이혼 확률 예측'은 배제(교차검증 실패) |
| 사랑의 언어 5가지 | ★★☆☆☆ | 보조 참고만. '주 언어 하나' 전제는 반박됨 → 낙인 금지 |

> **심리상담 트랙 필수 배제 규칙**
> ① Gottman '94% 이혼 예측'은 엔진에 넣지 않는다 — 사후 재구성일 뿐 교차검증 시 예측력 급락.
> ② '당신의 사랑의 언어는 X' 같은 유형 낙인 금지 — 다섯 언어 응답이 서로 강하게 상관되어 전제 자체가 반박됨.
> ③ 애착도 '회피형/불안형' 상자가 아니라 상태·맥락 언어로.

### 3.2 심리상담 트랙 해석 로직 — EFT 악순환 고리

2층 해석의 핵심. 표면 행동을 다음 순서로 번역한다.

1. 표면(비난/방어) 아래의 1차 정서(두려움·외로움·수치심)를 찾는다
2. 그 정서를 애착 욕구(안전감·수용·연결)로 번역한다
3. 두 사람의 반응이 서로를 자극하는 악순환 고리를 구조화한다

*예: 아내의 비난 = 버려질까 봐 두려운 항의 / 남편의 담쌓기 = 실패자로 느껴져 얼어붙음 → 서로가 서로의 공포를 방아쇠*

### 3.3 기독교 트랙 — 신학 기조 확정: Powlison / Keller / Tripp

SBC 2002 결의('치료 문화 속 성경의 충분성')와 2005 남침례신학교 커리큘럼 전환 이후, 성경적 상담은 제도화된 대형 시장이다. 단 **'성경적 상담'도 단일하지 않다**. 엔진은 1세대(Adams식 직면)가 아니라 2세대(Powlison/Keller/Tripp)를 기본 기조로 확정한다.

| 세대/성향 | 대표 인물 | 엔진 채택 여부 |
|---|---|---|
| 1세대 (Nouthetic) | Jay Adams | 기본 배제 — 죄 '먼저 직면'은 통역 목적과 상충, 방어·이탈 유발 |
| 2세대 (Biblical) | Powlison · Keller · Tripp · Welch | 기본값(default) — 먼저 듣고 이해, 은혜 우선 순서 |

**채택 근거:** 통역의 본질은 '먼저 이해시키는' 행위인데, 권면적 상담은 '먼저 죄를 지적'하는 방향이라 목적이 상충한다. 상처받은 상태로 들어온 부부에게는 은혜가 변화를 만든다는 복음적 순서(Powlison/Keller)가 구조적으로 맞다.

### 3.4 기독교 트랙 — 6개 해석 렌즈

기독교 상담 전문가 감수를 거친 6개 렌즈. 2층 해석에서 심리상담 트랙의 'EFT 고리'를 대체한다.

| 렌즈 | 내용 |
|---|---|
| ① 성경의 충분성 | 최상위 전제. 성경이 마음의 깊은 필요에 충분히 답한다. 순수 성경형 모드에서 심리학 이론을 판단 근거로 인용하지 않음 |
| ② 마음(Heart) 신학 | Powlison 핵심. 행동이 아니라 마음을 봄. X-ray 질문: '이 순간 내 마음은 무엇을 예배하는가' |
| ③ 우상숭배 동기분석 | Powlison/Keller. 갈등 근원을 '좋은 것을 궁극의 것으로 삼은 마음의 우상'으로. 정죄 아닌 진단적 자비의 언어 |
| ④ 성화로서의 결혼 | Tripp. 결혼은 행복 도구가 아니라 그리스도를 닮게 빚으시는 도구. 갈등조차 성화의 기회 |
| ⑤ 언약(Covenant) | 결혼은 계약 아닌 하나님 앞의 언약(엡 5장). 그리스도와 교회의 반영. 자기희생적 사랑(아가페)이 목표 |
| ⑥ 죄·회개·용서·화목 | 성경적 고유 변화 메커니즘. 복음에 근거한 용서 — 그리스도가 나를 용서하신 은혜의 관점 |

> **기독교 트랙 기본 동작 순서 (복음의 순서)**
> 1. 경청·이해 — 표면 말 아래 마음의 갈망을 먼저 헤아림
> 2. 은혜 안착 — 정죄 아닌 은혜의 안전망 확보
> 3. 마음 조명 — '이 순간 내 마음이 무엇을 예배하는가'(자기 성찰)
> 4. 소망 제시 — 배우자를 하나님이 빚으시는 미래 모습으로
> 5. 회개·용서 — 자유케 하는 회개, 복음에 근거한 용서
>
> **절대 금지:** 배우자를 향한 죄 지적 출력 / Adams식 '먼저 직면' / 은혜 없는 죄 언어(자책·수치 강화)

**기독교 트랙 헌법 (톤 균형추):** Powlison의 통찰을 엔진 톤의 헌법으로 삼는다: 사람을 '문제'가 아니라 **고난받는 자이자 죄인인 동시에 사랑받는 자**로 본다. 통역이 배우자를 악당으로도, 사용자를 죄인으로만도 그리지 않게 하는 균형추다.

## 4. 프롬프트 아키텍처 — 코드화 청사진

이 장이 프롬프트 라이브러리로 직결된다. 프롬프트는 '공통 시스템 프리앰블 + 트랙 모듈 + 모드 모듈 + 강도 파라미터 + 안전 오버라이드'의 조립 구조로 설계한다. 재사용성과 유지보수성을 위해 모듈화한다.

> ✅ **구현 완료**: `translation-prompts.ts` — 이 장의 설계가 그대로 코드로 전환됨.

### 4.1 프롬프트 조립 구조

| 모듈 | 역할 | 가변성 |
|---|---|---|
| 공통 프리앰블 | 역할 정의·통역자 정체성·전역 안전 규칙 | 고정 |
| 트랙 모듈 | 심리상담(EFT) / 기독교(6렌즈) 해석 프레임 주입 | 택1 |
| 모드 모듈 | 수신 / 발신 / 중재 / 관점 각 입출력 형식 | 택1 |
| 강도 파라미터 | 심리상담: 감정깊이 / 기독교: 신학강도·목양톤 | 슬라이더값 |
| 관계 기억 주입 | 이 부부의 누적 프로파일(반복주제·패턴) | 동적 |
| 안전 오버라이드 | 폭력·위기·의료의뢰 감지 시 최상위 개입 | 상시 감시 |

### 4.2 공통 프리앰블 핵심 규칙 (양 트랙 공통)

- **통역자 정체성:** AI는 판결자·목회자·치료사가 아니라 통역자다. 답이 아니라 가설을 제시하고 최종 확인은 당사자에게 넘긴다.
- **단정 금지:** '배우자는 외롭다'(단정) → '외로움의 신호일 수 있다. 물어보면 어떨까'(가설+검증).
- **편들기 금지:** 항상 양쪽의 취약함을 동시에 드러낸다. 한쪽 편들기는 무기화를 낳는다.
- **낙인 금지:** 유형 상자에 가두지 않고 상태·맥락 언어만 사용.
- **안전 우선:** 폭력·강압적 통제 신호 시 통역 중단, 안전·전문기관 안내로 전환.

### 4.3 트랙별 시스템 프롬프트 골격

**심리상담 트랙 (EFT)**
지시 요지: 표면 행동 → 1차 정서 → 애착 욕구 → 악순환 고리 순으로 통역하라. 진단명·이혼예측·유형낙인을 쓰지 마라. 두 사람이 고리에 함께 갇혔음을 보여라.

**기독교 트랙 (Powlison/Keller/Tripp)**
지시 요지: 복음의 순서(경청→은혜→마음조명→소망→회개/용서)를 따르라. 6렌즈로 해석하되 죄·우상 렌즈는 자기 성찰용으로만. 배우자 정죄 출력 금지. 논쟁적 교리는 담임목회자에게 위임. Adams식 선(先)직면 금지.

### 4.4 강도 슬라이더 사양

| 슬라이더 | 트랙 | 범위 | 효과 |
|---|---|---|---|
| 감정 깊이 | 심리상담 | 표면 ↔ 심층 | 1차 정서·애착까지 파고드는 정도 |
| 신학 강도 | 기독교 | 통합형 ↔ 순수 성경형 | 심리학 언어 허용도(통합←→성경만) |
| 목양 톤 | 기독교 | 경청·은혜형(기본) ↔ (제한적)직면형 | 2세대 기본값. 직면형은 극히 제한적으로만 노출 |

## 5. 멀티모달 분석 · 동의 게이트

텍스트 입력의 최대 약점은 '사용자가 이미 편집·왜곡한 대화만 들어온다'는 것이다. 음성·영상은 가공되지 않은 상호작용 원본을 직접 분석하므로 통역 정확도가 차원이 다르다. **마음수달·마음곁에 이미 구현된 녹음·영상 분석 기능을 재사용**하므로 개발 효율도 높다. 단, 이 기능은 양날의 검이다 — 동의 없는 캡처는 감시·스토킹 도구가 된다. 따라서 '동의 게이트'가 기능의 전제 조건이다.

### 5.1 멀티모달이 이론적으로 강력한 이유

이건 편의 기능이 아니라 이론 뼈대(3장)를 완성하는 입력이다.

- **경멸 탐지의 완성:** 경멸은 대부분 비언어(눈굴림·한숨·비웃는 어조)로 표현되어 텍스트로는 못 잡는다. Gottman의 원본 방법론 자체가 표정·어조 관찰이었다 — 영상 분석은 그 관찰 방식에 가장 근접한 입력이다.
- **'거친 시작' 실측:** 대화 첫 3분의 어조가 전체를 좌우한다는 명제를, 음성은 실제 톤·속도·볼륨으로 측정한다(텍스트는 추정만 가능).
- **EFT 1차 정서의 신체 신호:** 떨리는 목소리·방어적 자세·시선 회피 등 '표면 행동 아래 1차 정서'의 신체 단서가 영상에 담긴다.

**심리적 타당성:** 부부 문제는 당사자 모두 '문제가 있음'은 알지만 해결 방법을 못 찾는 경우가 많다. 쌍방 합의 하의 녹음·영상은 '무엇이 실제로 일어나는가'를 객관화해, 서로를 탓하는 대신 패턴을 함께 보게 만든다.

### 5.2 동의 게이트 — 마음커플 '코드 전달' 방식 재사용

마음커플의 커플 심리검사 초대 코드 방식을 그대로 확장한다. 새로 만드는 것이 아니라 **검증된 자산을 재사용**해 개발 효율과 법적 안전을 동시에 확보한다. 핵심 원칙: 동의는 UX 안내가 아니라 시스템 게이트다 — 동의 없이는 캡처 기능 자체가 활성화되지 않는다.

> ✅ **구현 완료**: `translate-route.ts`의 `/api/consent/*` 3종 엔드포인트.

| 단계 | 동작 |
|---|---|
| 1. 요청 생성 | 발신자가 녹음/영상 분석 세션을 요청 |
| 2. 코드 발급 | 시스템이 '동의 요청 코드' 발급 (마음커플 초대코드 로직 재사용) |
| 3. 코드 전달 | 배우자에게 링크/앱 내 알림으로 전달 |
| 4. 고지·동의 | 배우자가 코드로 진입 → 무엇을·어떻게 쓰는지·삭제 권리 고지 → 명시적 동의 |
| 5. 캡처 활성화 | 쌍방 동의 확인된 세션에서만 녹음/영상 캡처 버튼 활성화 |
| 6. 분석·종료 | 분석 → 통역 → 세션 종료 시 원본 처리 정책 적용 |

> **동의 게이트 3대 원칙 (감시 방지)**
> ① 동의 없이는 캡처 버튼 자체가 비활성. '일단 녹음 후 나중에 동의'는 불가능 — 순서가 뒤집히면 감시 도구가 된다.
> ② 동의는 세션 단위이며 언제든 철회 가능. 배우자가 철회하면 즉시 캡처 중단. 영구 권한이 되지 않는다.
> ③ 동의 주체 = 녹음 대상 본인. 대리 동의 불가. 배우자 본인 계정/기기에서만 동의.

> **법적 근거 (한국)**
> - 통신비밀보호법상 대화 당사자가 아닌 제3자의 몰래 녹음은 불법이나, 부부가 상호 동의한 '자신들의 대화' 녹음은 합법 영역이다.
> - 동의 게이트는 이 합법 요건(쌍방·명시적·자기 대화)을 시스템으로 강제해 법적 리스크를 원천 차단한다.
> - 생체·음성·영상은 민감정보이므로 동의 고지에 수집 항목·목적·보관기간·삭제권을 명시한다.

### 5.3 원본 데이터 처리 정책

- 분석은 '구조화 요약'만 관계 기억에 저장하고, 원본 음성·영상은 기본적으로 세션 종료 시 삭제(사용자가 명시적으로 보관 선택 시에만 암호화 보관).
- 원본 보관 시에도 열람·삭제 권한은 쌍방 모두에게. 한쪽이 삭제 요청하면 삭제.
- 멀티모달 원본은 어떤 경우에도 제3자 공유·외부 전송 금지.

## 6. 데이터 구조 — 관계 기억 (해자의 심장)

단순 대화 로그가 아니라 '이 부부에 대한 누적 관계 프로파일'을 만든다. 첫 대화와 100번째 대화의 통역 품질이 확연히 달라야 한다. 이것이 경쟁 AI가 복제 불가능한 개인화다. 마음커플의 D1 스키마를 확장 재사용한다.

**관점 통역과의 맞물림:** '상대 관점 프로파일'이 쌓일수록 관점 통역(2.2-D)의 정확도가 올라간다. 배우자가 자주 상처받는 지점과 인식 습관을 기억이 축적하면, '상대는 이걸 어떻게 느꼈을까'의 답이 일반론이 아니라 이 배우자에 특화된다. 이론(EFT·Keller)·기억·관점이 삼각으로 맞물리는 지점이다.

### 6.1 관계 프로파일 핵심 필드 (개념 스키마)

> ✅ **구현 완료**: `translate-route.ts` 주석의 D1 스키마 (`relation_memory` 등 4개 테이블).

| 영역 | 저장 내용 | 트랙 |
|---|---|---|
| 반복 갈등 주제 | 돈·시가·육아·집안일·성 중 뇌관 식별 및 빈도 | 공통 |
| 심리상담 프로파일 | 애착 경향(차원값)·갈등 스타일·자주 나타난 4독소 | 심리상담 |
| 기독교 프로파일 | 반복되는 마음의 우상 패턴·성화 주제·언약 인식 수준 | 기독교 |
| 성공 공식 | 효과 있었던 표현 = 이 부부만의 통(通)한 순간 | 공통 |
| 상대 관점 프로파일 | 배우자가 세상을 보는 방식·자주 상처받는 지점·인식 습관 | 공통 |
| 슬라이더 설정 | 트랙 선택·신학강도·목양톤 사용자 기본값 | 공통 |
| 안전 플래그 | 위기·의료의뢰·학대 감지 이력(민감·암호화) | 공통 |

> **데이터 설계 3원칙**
> ① 프라이버시 우선: 관계 내밀 정보는 해외에서도 최대 시장 저해 요인. 익명처리·암호화·'대화 저장 안 함' 옵션을 처음부터 탑재.
> ② 개인정보 최소 수집 + 관계 프로파일은 요약본으로: 원문 장기 저장 대신 통역에 필요한 구조화 요약을 보관.
> ③ 데이터 자산화: 통역 요청·교정·성공 케이스는 향후 파인튜닝·품질개선의 독점 데이터(동의 기반).

## 7. 개선 활동 · 피드백 루프 · 커뮤니티 (회복 레이어)

통역은 이해를 만들지만, 관계는 이해만으로 바뀌지 않는다. "알았는데, 그래서?"에서 서비스가 죽는다. 회복 레이어는 깨달음과 행동 사이의 간극을 메우는 층이며, 서비스 완성도의 승부처다.

**순환 구조:** 통역(이해) → 활동 제안(행동) → 실행 → 피드백(성공/실패) → 재해석 → 관계 기억 축적 → 다음 제안이 더 정교해짐 → (동의 시) 커뮤니티 익명 공유 → "나만 그런 게 아니구나"

### 7.1 개선 활동 제안 — 4모드 출력에 승격

> ✅ **구현 완료**: 4모드 전체 출력 스키마에 `improvement` 블록 (`translation-prompts.ts`).

모든 통역 출력에 개선 활동 블록이 포함된다: `action`(활동) · `why_this`(통역과의 연결) · `expect`(실패 면역) · `checkin`(확인 질문).

**활동 품질 6원칙:**
1. **문턱이 낮을 것** — 10분 이내·오늘·혼자 시작 가능·상대 협조 불필요. "가족 식사 하세요" ❌ → "퇴근길에 붕어빵 하나 사서 말없이 식탁에" ⭕
2. **통역과 정확히 연결될 것** — 범용 조언이 아니라 방금 그 통역에서 파생된 활동. 통역의 논리가 활동의 논리로.
3. **관계 기억이 활동을 개인화할 것** — "이 관계에 통했던 것"이 쌓일수록 제안이 진화. 100번째가 첫 번째보다 좋아지는 지점.
4. **실패를 설계에 포함할 것** — 제안 시점에 실패 면역을 심는다: "처음엔 어색해하실 수 있어요. 그것도 정상이에요."
5. **트랙별 결이 다를 것** — 심리상담: 안전감을 만드는 작은 접촉·취약함 드러내기 / 기독교: 축복 기도·감사 나눔 등 이미 존재하는 영적 실천을 활동의 그릇으로.
6. **확인 질문 하나로 닫을 것** — 부담 없는 체크인이 피드백 루프의 입구.

### 7.2 피드백 루프 — 성공/실패 경험의 입력

> ✅ **구현 완료**: `buildFeedbackPrompt()` + `POST /api/feedback` + D1 `activity_log`.

**피드백은 보고서가 아니라 탭이다.** 3단 구조:
1. 필수(탭 1회): 해봤어요 / 하다 말았어요 / 못 했어요
2. 선택(탭 1회): 상대 반응 — 좋았어요 / 어색했어요 / 냉담했어요 / 오히려 싸웠어요
3. 선택(자유입력): 무슨 일이 있었는지

**반응별 처리 (핵심은 실패 처리):**

| 반응 | 엔진 응답 |
|---|---|
| 좋았어요 | 무엇이 통했는지 짚고 → 성공 공식으로 관계 기억에 축적 |
| 어색했어요 | 정상 반응. 어색함 = 변화가 시작된 증거로 재해석 |
| 냉담했어요 | 실패 아님. 실패 면역 상기, "씨앗은 심겼다". 다음은 더 가볍게 |
| 오히려 싸웠어요 | 중재 통역으로 자연 연결. 사용자 자책 방지 최우선 |
| 못 했어요 | 판단하지 않음. 못 한 이유에 관계의 단서가 있을 수 있음 |

**데이터 원칙:** activity_log에는 활동·상태·반응만 저장. 자유 서술은 응답 생성에만 쓰고 저장하지 않는다(프라이버시). 이 루프가 쌓이면 "어떤 통역 뒤의 어떤 활동이 어떤 관계에서 통했는가"라는 독점 데이터가 된다.

### 7.3 커뮤니티 — "나만 그런 게 아니구나"

관계 갈등의 고통 중 상당 부분은 고립감이다. 커뮤니티는 이를 깨는 장치이며, 관계 서비스답게 설계한다.

- **익명 필수** — 가족 얘기는 실명으로 못 쓴다. author_hash만 저장, user_id 직접 저장 금지.
- **글의 단위는 '경험'** — 상황 → 시도한 활동 → 결과의 구조화된 공유. 피드백 기록을 (본인 동의 시) 익명 공유로 전환하는 흐름.
- **주제별 방** — couple / teen_parent / retire_dad / holiday / caregiving 등. 같은 폭풍을 지나는 사람들끼리.
- **공감 반응만, 순위·경쟁 없음** — 좋아요 랭킹이 생기면 자극적인 글이 이기고 커뮤니티가 죽는다.

### 7.4 AI 사전 검수 — 게시 전 게이트

> ✅ **구현 완료**: `buildModerationPrompt()` + `POST /api/community/post` (검수 통과분만 저장).

**사후 삭제가 아니라 사전 검수.** 게시 버튼을 누르면 AI가 먼저 검토하고, 문제가 있으면 게시 전에 안내한다. 이미 노출된 뒤 지우는 것보다 안전하다.

**검수 기준 (차단 대상):**

| 분류 | 내용 | 처리 |
|---|---|---|
| profanity | 욕설·모욕 | 사유 안내 + 수정 유도 |
| personal_info | 특정인 식별 정보 ("OO동 시어머니", 실명, 직장) | 사유 안내 + 수정 유도 |
| relationship_destruction | 타인에게 단절 지시 ("이혼하세요") — 본인 경험 서술은 허용 | 사유 안내 + 수정 유도 |
| attack | 특정인·집단(성별·세대·종교) 혐오 | 사유 안내 + 수정 유도 |
| crisis | 자해·폭력 피해 암시 | **삭제가 아닌 보호 분기** — 전문기관 연결 안내 |

**검수의 품격 — 말없는 삭제 금지:**
- 거부 시 반드시 사유를 안내하고(예: "특정인을 식별할 수 있는 정보가 포함되어 있어요"), 문제 부분과 수정 제안을 함께 제공해 [수정하기]로 재게시할 길을 연다. 글 쓴 정성을 존중한다.
- 판단이 애매하면 허용 쪽으로. 감정 토로·하소연은 이 커뮤니티의 본질이다.
- 위기 신호는 검열이 아니라 돌봄으로 — 8장 안전 오버라이드와 동일 원칙.

## 8. MVP 명세 — 부부 × 이중 트랙

'모든 관계'는 비전, 출시는 '부부' 하나로 좁힌다. 단 트랙은 처음부터 심리상담·기독교 병행으로 제공한다(사용자가 온보딩에서 선택). 부부는 이탈 비용이 높아 지불의사가 크고, 기독교 트랙은 교회 채널로 낮은 CAC 진입이 가능하다.

### 8.1 화면 구성

| 화면 | 핵심 기능 | 비고 |
|---|---|---|
| 온보딩 | 트랙 선택(심리상담/기독교) + 슬라이더 초기설정 + 안전 고지 | 기독교 선택 시 신학강도·목양톤 추가 질문 |
| 동의 요청 | 녹음/영상 분석용 코드 발급·전달 (마음커플 방식) | 쌍방 동의 전 캡처 불가 |
| 멀티모달 캡처 | 쌍방 동의 세션에서 녹음/영상 입력 → 비언어 신호 탐지 | 세션 단위·철회 가능 |
| 홈 | 4모드 진입(수신·발신·중재·관점) + 최근 통역 | 입력 마찰 최소화가 핵심 |
| 수신 통역 | 배우자 말 입력 → 마음/애착 통역 + micro-action 제안 | 카톡 붙여넣기·스크린샷 OCR |
| 발신 통역 | 내 말 입력 → 부드러운 시작으로 재작성 + 관점 미리보기 | 상대가 받을 느낌 프리뷰 |
| 중재 통역 | 대화 전체 입력 → 양쪽 입장·오해지점·다음 한마디 | 편들기 금지 규칙 적용 |
| 관점 통역 | 같은 사건을 배우자 입장 버전으로 → '상대는 어떻게 느꼈을까' | 상대 관점 프로파일과 맞물림 |
| 활동 체크인 | 제안받은 활동의 실행 피드백 (탭 3단) | 실패 재해석 응답, 성공 공식 축적 |
| 커뮤니티 | 주제별 익명 경험 공유 + 공감 반응 | AI 사전 검수 게이트, 순위 없음 |
| 관계 기억 | 누적 프로파일·반복 패턴·성공 공식 열람 | '또 시가 얘기에서 막혔네요' |
| 연결 | 위기 시 전문기관 / 신앙인은 목회·교회 상담 연결 | 대체 아닌 다리(bridge) |

### 8.2 MVP 범위 컷 (해야 할 것 / 미룰 것)

**MVP 포함:**
- 이중 트랙 병행(심리상담 EFT + 기독교 6렌즈) + 슬라이더
- 4모드(수신·발신·중재·관점) + 개선 활동 블록
- 피드백 루프(활동 체크인 → 재해석 → 성공 공식 축적)
- 커뮤니티 기본형(주제별 익명 방 + AI 사전 검수 + 공감 반응)
- 관계 기억 기본형(반복주제·성공공식)
- 안전 오버라이드 + 연결 다리
- 혼자 써도 되는 설계(배우자 동의 불필요)
- **선택적 공유 브리지·함께 보기**(ADDENDUM 01 §1로 MVP 편입): 사용자가 고른 통역/활동만 건별 명시 공유 + 배우자 초대(마음커플 초대코드 패턴). 수신통역·이력·기억·피드백은 공유 금지, T1/T2 안전 세션은 공유 차단.

**출시 후로 미룸:**
- 타 관계(성인 부모-자녀·직장) 확장
- 양방향 계정(부부 각자 앱) **실시간 동기화**(동시 세션·커플 대시보드) — 비동기 선택 공유는 MVP로 앞당김
- 상담사 마켓플레이스·유료 세션 예약

## 9. 안전 · 윤리 가드레일 (방어막)

가드레일은 규제·소송·평판 리스크를 막는 자산이다. 양 트랙 공통 규칙과 기독교 트랙 고유 위험을 분리해 규정한다.

### 9.1 공통 안전 오버라이드 — 분리 보호 3단계 기준 (최상위)

> ✅ **구현 완료**: `translation-prompts.ts`의 SAFETY_OVERRIDE — 모든 프롬프트에 상시 포함.

**설계 전제의 전환:** 엔진의 기본 전제는 '관계 회복'이지만, 학대 상황에서는 그 전제가 뒤집힌다. 한국 법은 분리를 명시적으로 지지한다 — 아동복지법(학대 정의), 아동학대처벌법(격리·접근금지 응급조치), 민법 제924조(친권 상실·제한), 가정폭력처벌법(피해자 보호명령), 노인복지법(노인학대). "분리가 필요한 상황"은 법이 이미 유형화했고, 엔진은 이를 따른다.

| 단계 | 신호 | 엔진 동작 |
|---|---|---|
| **T1 즉시 분리** | 신체 폭력·성적 학대·생명 위협·심각한 방임 | 통역·회복 활동 **전면 중단**. "지금은 이해가 아니라 안전을 확보할 때" 명시. 긴급 자원 즉시 안내(112 / 청소년 1388 / 여성긴급전화 1366 / 노인보호 1577-1389). 분리·신고·보호명령이 법이 보장하는 권리임을 알림 |
| **T2 지속 학대 패턴** | 반복적 정서 학대·강압적 통제·가스라이팅 | 상대에게 다가가는 회복 활동 제안 **금지**. ① 자책 해소 ② 거리두기 정당화("법도 이를 지지합니다") ③ 자기 보호 활동(기록·경계 설정·전문가 연결)만 제안. Bowen 관점: 이 상황에서는 거리 자체가 분화 |
| **T3 일반 갈등** | 통상적 부부·가족 갈등 | 통상 통역 + 회복 레이어 |

**절대 금지 (T1·T2, 어떤 트랙·슬라이더도 무력화 불가):**
- 죄책감 유발 출력: "그래도 부모님인데", "네가 이해하면", "가족이니까 참아야" 전면 금지
- 가해자의 행동을 '마음의 신호'로 통역해 정당화하는 것
- 기독교 트랙에서 공경·용서·인내의 언어로 학대 수인을 권하는 것 — **공경은 학대를 견딜 의무가 아니며, 안전한 거리에서의 공경도 공경이다**

**기타 위기 신호:** 자해·자살 신호 → 위기 자원 안내(구체적 방법 언급 금지) / 정신과적 질환·치매 의심 → 의료 의뢰 권고, '죄의 문제로만 환원 금지'

### 9.2 멀티모달 고유 위험 (감시·판정)

> **녹음·영상 분석의 3대 위험과 규칙**
> ① 몰래 캡처 → 감시·스토킹 도구화: 동의 게이트(5.2)로 원천 차단. 동의 없는 캡처 불가.
> ② 영상 판정의 단정: '배우자는 경멸하고 있다'(단정) 금지. 비언어 신호도 가설로 제시 — '경멸의 신호일 수 있다'.
> ③ 원본 유출: 세션 종료 시 원본 삭제 기본값, 제3자 전송 절대 금지(5.3).

### 9.3 기독교 트랙 고유 위험 4종

| 위험 | 엔진 규칙 |
|---|---|
| '죄' 프레임의 무기화 | 죄·우상 렌즈는 자기 성찰용으로만. 배우자 정죄 도구로 출력 금지. '배우자 죄 지적' 요청 거부 |
| 학대에 인내·복종·용서 강요 | 폭력·강압 신호 시 성경 언어 즉시 중단, 안전 우선. '성경은 학대를 견디라 하지 않는다' 명시 |
| 교단·신학 차이 침범 | 이혼·재혼·성역할 등 논쟁 교리는 단정 않고 담임목회자에게 위임 |
| 목회적 돌봄 대체 착각 | 통역은 교회 공동체·목회 상담으로 연결하는 다리. 대체 아님을 명시 |

**근거:** SBC조차 학대는 성경적 상담으로 덮지 않는다. 성경적 상담 표준도 가정·성적 학대는 신고, 일부 질환은 의료 의뢰를 명시한다. 엔진의 가드레일은 이 표준과 정합한다.

## 10. 자산화 로드맵 · 수익 구조

### 10.1 6단계 전환 로드맵

| 단계 | 산출물 | 상태 |
|---|---|---|
| 1. 엔진 IP 고정 | 본 마스터 문서 | ✅ 완료 |
| 2. 프롬프트 코드화 | 트랙·모드·슬라이더 프롬프트 라이브러리 | ✅ 완료 (`translation-prompts.ts`, `translate-route.ts`) |
| 3. 케이스 뱅크 | 상담사 감수 통역 케이스 20~30건 | 진행 예정 |
| 4. MVP 출시 | 부부 × 이중 트랙 + 회복 레이어 | 개발 착수 (클로드코드) |
| 5. 유통 채널 선점 | 교회·교단·기독교방송 B2B2C 채택 | 병행 |
| 6. IP·법적 방어막 | 상표·면책·감수 마크 | 출시 전 필수 |

### 10.2 이중 트랙의 이중 수익

| 트랙 | 시장 | 채널 | 수익 |
|---|---|---|---|
| 기독교 | 신앙 부부 | 교회·교단·기독교방송 | B2B2C(교회 라이선스) + B2C 구독 |
| 심리상담 | 일반 부부 | 앱스토어·제휴 | B2C 구독 + 상담 연계 수수료 |

> **진입 순서 전략 (핵심)**
> 기독교 트랙을 '먼저' 출시해 교회 채널로 낮은 CAC에 검증·매출을 확보하고, 그 신뢰·현금흐름으로 심리상담 트랙(경쟁 치열·CAC 높음)에 진입한다.
> 대부분의 경쟁자는 반대로 하다 마케팅비에 소진된다. 상담사 감수 역량 + 기존 교회 파트너십이 이 순서를 가능하게 하는 유일한 조건이다.

### 10.3 자산 재사용 매트릭스 (개발 효율)

| 기존 자산 | 재사용 대상 | 신규 개발 |
|---|---|---|
| 마음커플 (JWT SSO·D1·상담연계) | 인증·세션·연결 다리 | 부부 특화 통역 프롬프트 |
| 마음수달·마음곁 (녹음·영상 분석) | 멀티모달 탐지 엔진 | 부부 상호작용 비언어 신호 모델 |
| 마음커플 초대코드 로직 | 쌍방 동의 게이트 | 세션 단위 동의·철회 관리 |
| 마음풀 (심리검사·상담엔진·Toss) | 진단 프로파일·결제 | 관계 기억 저장 구조 |
| Cloudflare 스택(Hono/Workers/D1/KV) | 동일 배포 패턴 | 이중 트랙 분기 로직 |
| CTS·기독교TV 파트너십 | 교회 유통 채널 | 기독교 트랙 감수 케이스 뱅크 |

**결론:** 자산화의 급소는 ①엔진 IP 문서화(본 문서) → ②프롬프트 코드화 → ③상담사 케이스 뱅크 → ④부부×이중트랙 MVP → ⑤교회 채널 선점 순서이며, 그 위에 상표·면책·감수 마크로 방어막을 씌운다. 두 트랙은 처음부터 병행 설계되어 하나의 엔진이 두 시장을 커버한다.

### 10.4 후속 확장 — 부모-자녀 세대 통역 (별도 패키지)

마음부부 완성 후, 동일 엔진(2트랙×4모드×관계기억×회복레이어×분리보호)을 재사용해 부모-자녀 세대 통역 앱을 후속 개발한다. **상세 기획은 별도 개발 패키지(부모자녀_개발패키지)를 참조** — 본 문서에는 담지 않는다.

**마음부부 개발 시 후속 앱을 위해 반드시 해둘 것 (상속 준비):**
- 계정 스키마에 생년월일 + 연령등급(teen/adult/senior) 필드 포함 — 마음부부는 성인 전용 게이트만 적용하되, 필드 자체는 지금 심어 후속 앱이 3층 연령 체계를 상속받게 한다.
- 통역 엔진의 관계 컨텍스트(relation type)를 파라미터화 — 현재는 'couple' 고정이지만 하드코딩하지 않는다.
