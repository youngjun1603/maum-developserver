## 2. 이슈별 상세 (S1 금전 항목 판단 근거)

- **R-37 (S1 금전손실 방지)**: 지시서는 "셀프환불(L1186)·관리자환불(L4570) 2곳 하드코딩"으로 봤으나 **실측 결과 실제 새는 곳은 관리자환불 한 곳**이었다(셀프환불은 `refPkg.service !== 'phyweb'`로 이미 400 차단, 프론트 환불 버튼도 `credits:0` 상품엔 안 뜸). 원인도 하드코딩이 아니라 `if (admPkg?.service === 'phyweb')` 분기라 수달·곁이 빠진 것. **수정**: 조건을 `if (admPkg?.service && admPkg.grantType)`로 넓히고 `SERVICE_API[service]`+6필드 `signSso`로 revoke 호출 + `external_grants status='revoked'`. 수달·곁 수신측도 `revoke`에 대상 서비스 검사 추가(각 400 가드). **판단**: 가격·상품 미변경, 추가형(기존 phyweb 경로 유지).
- **R-38/R-39 (S1)**: CTS 웹훅을 마음풀 패턴으로 교체 — Authorization 헤더 강제 대신 **토스 API `GET /v1/payments/{paymentKey}` 재조회**(TOSS_SECRET_KEY) + `orderId`(`charge_<chargeId>_<ts>`)→chargeId DB 역산 + `totalAmount === charge.amount` 검증. deliverGrant 분기 없음(CTS는 자체 크레딧).
- **R-40 (S1)**: `user_subscriptions` INSERT의 빈 `catch{}`를 `catch(e){ console.error(...) }`로 — 실패가 조용히 삼켜지던 것 표면화.
- **R-47**: 정산 요약·통계 share를 `Math.floor(revenue*rate)`가 아니라 **`partner_commissions` 원장 SUM(share_amount)** 기준으로 통일. 지시서 지적대로 절사 차이보다 **모집단·기간 기준 차이**(요약=credit_charges 전체 vs 원장=적립조건 통과분)가 더 컸다.
